# 第 2 章：Transformer 架构（Grok 基础）

在第 1 章中，我们介绍了**两阶段推荐管道**，解释了系统依赖于两个关键模型：快速检索模型和强大的排序模型。这两者都需要对用户行为和内容特征有深入的理解。

这种==深入的理解由同一个底层神经网络引擎提供：**Transformer 架构**==，改编自高性能开源 Grok-1 模型。这是 `x-algorithm` 的核心

## 什么是 Transformer？（上下文引擎）

想象一下，我们正在尝试理解一个用要点写成的复杂食谱：

1.  添加面粉。
2.  混合鸡蛋。
3.  烘烤 30 分钟。

如果我们孤立地阅读步骤 3（"烘烤 30 分钟"），我们不知道*烘烤什么*。我们需要步骤 1 和 2 的上下文。

传统计算机可能会线性读取步骤并忘记早期的上下文。**Transformer** 模型被设计为同时阅读所有步骤，并立即计算每条信息对最终结果的重要程度。

在 Phoenix 中，"步骤"是用户个人资料、他们过去的交互（喜欢、跳过）和候选帖子的嵌入（数值表示）。Transformer 的工作是读取整个序列并理解它们之间的关系。

## 秘密成分：自注意力

Transformer 架构的核心突破是**自注意力**。这种机制允许模型动态地权衡序列中每个标记（嵌入）相对于其他每个标记的重要性。

### 自注意力的工作原理

当 Transformer 处理特定用户的数据时，它会查看序列：`[用户个人资料, 喜欢的帖子 A, 跳过的帖子 B, ...]`

为了让模型理解用户个人资料，自注意力计算一个分数（或"权重"），表示用户个人资料应该在多大程度上关注喜欢的帖子 A 与跳过的帖子 B。

| 交互类型         | 注意力权重（示例） | 上下文洞察                           |
| :--------------- | :----------------- | :----------------------------------- |
| **喜欢的帖子 A** | 高 (0.8)           | "这个帖子与用户当前的理解高度相关。" |
| **跳过的帖子 B** | 低 (0.1)           | "这个历史项目现在不太重要。"         |
| **作者 C**       | 中 (0.5)           | "作者中等重要。"                     |

然后，Transformer 使用这些注意力权重为用户个人资料创建一个全新的、丰富的嵌入——一个已经吸收了其历史中最重要上下文的嵌入。

## Grok 基础架构

Phoenix 中使用的核心 Transformer 引擎在结构上与 Grok-1 模型发布的高效且强大的架构相同。这确保了可扩展性和强大的序列建模能力。

Transformer 由多个相同的**解码器层**堆叠组成。每一层都进一步完善上下文理解。

### 解构解码器层

每次数据通过一层时，它都会经历两个主要步骤：

1.  **多头注意力（MHA）：** 计算上下文并混合信息。
2.  **密集块（FFN）：** 非线性处理混合信息。

我们可以在 `grok.py` 文件中看到这种结构，其中 `Transformer` 模块循环遍历许多 `DecoderLayer`：

```python
# phoenix/grok.py（简化版）

@dataclass
class Transformer(hk.Module):
    num_layers: int  # 例如，24 层深
    # ... 其他配置细节 ...

    def __call__(self, embeddings, mask, candidate_start_offset=None):
        h = embeddings
        
        # 1. 重复应用层
        for i in range(self.num_layers):
            # DecoderLayer 包含 MHA 和 DenseBlock
            decoder_output = DecoderLayer(...)(h, mask, padding_mask)
            h = decoder_output.embeddings
        
        return TransformerOutput(embeddings=h)
```

### 来自 Grok 的关键组件：RoPE 和 RMSNorm

Grok 基础引入了专门的组件，使 Transformer 对复杂任务有效：

#### 1. 旋转嵌入（RoPE）

在处理序列时，项目的位置很重要。交互是在 10 秒前还是 10 天前？**旋转嵌入**在注意力计算发生*之前*以数学方式将位置信息注入嵌入中。这为模型理解空间或时间顺序提供了一种自然的方式。

RoPE 在 `MultiHeadAttention` 模块内实现：

```python
# phoenix/grok.py（简化的 RoPE 应用）

class MultiHeadAttention(hk.Module):
    # ... 初始化 ...

    def __call__(self, query, key, value, mask):
        # 1. 投影输入（Query 和 Key）
        query_heads = self._linear_projection(query, ..., name="query")
        key_heads = self._linear_projection(key, ..., name="key")

        # 2. 应用 RoPE 注入位置感知
        rotate = RotaryEmbedding(dim=self.key_size)
        key_heads = rotate(key_heads, seq_dim=1, offset=0)
        query_heads = rotate(query_heads, seq_dim=1, offset=0)
        
        # 3. 使用修改后的 Q 和 K 计算注意力
        # ...
```

#### 2. RMSNorm（层归一化）

Transformer 处理大量数值数据。为了在训练期间保持计算稳定和快速，它们需要归一化层。Grok 使用 **RMSNorm**（均方根归一化），这是传统 LayerNorm 的简化但高效的版本。

RMSNorm 在 MHA 和密集块之前和之后应用，以稳定数据分布：

```python
# phoenix/grok.py（简化的归一化钩子）

def hk_rms_norm(x: jax.Array) -> jax.Array:
    """使用默认设置对 x 应用唯一的 LayerNorm。"""
    # RMSNorm 只是根据均方的平方根对输入进行归一化。
    ln = RMSNorm(axis=-1, create_scale=True)
    return ln(x)
```

## Transformer 在 Phoenix 中的作用

Transformer 运行的确切方式根据推荐管道的阶段略有不同：

| 阶段               | 输入序列             | Transformer 目标                             | 使用注意力掩码？                                             |
| :----------------- | :------------------- | :------------------------------------------- | :----------------------------------------------------------- |
| **检索**（用户塔） | 用户 + 历史          | ==生成单个高度上下文化的用户向量==。         | 标准因果/双向                                                |
| **排序**           | 用户 + 历史 + 候选项 | 基于完整序列上下文为每个候选项==生成分数==。 | [Recsys 注意力掩码（候选项隔离）](04_recsys_attention_mask__candidate_isolation__.md) |

这个共享的强大引擎确保无论 Phoenix 是试图快速找到相关帖子还是精确评分，它都对用户有最好的上下文理解。
