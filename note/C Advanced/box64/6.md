# 第 6 章：C 代码解析

欢迎回来

在 [第 5 章：宏系统](05_macro_system_.md) 中，我们看到了 Box64 的预处理器如何处理原始 C 代码，处理 `#include`，删除注释，并熟练地展开所有宏，将复杂的 C 文本转换为干净的、完全展开的基本"单词"或"标记"流。现在我们有了这个有组织的标记流，接下来是什么？

这就是"C 代码解析"发挥作用的地方。想象一下我们有 C 程序的所有单个单词完美地排列出来。下一步是理解这些单词如何组合在一起形成有意义的句子、段落，最终形成一个完整的故事——C 程序的结构和逻辑。

## 挑战：理解 C 的语法结构

将 Box64 想象成一位技艺精湛的语言学家。在预处理器提供了一个整洁的单词列表之后，这位语言学家的工作是应用 C 语法的复杂规则来理解其含义。`int x;` 是变量声明吗？`func(a + b);` 是带有加法参数的函数调用吗？

C 语言有特定且严格的语法。它定义了关键字、标识符、运算符和符号必须如何排列才能形成有效的程序构造。为了让 Box64 正确生成包装器代码或分析程序，它*必须*理解这种语法结构。如果它误解了哪怕是一小部分，整个翻译都可能出错，导致在 ARM64 上运行 x86_64 程序时出现不正确的行为或崩溃。

**Box64 通过"C 代码解析"解决的核心问题是==获取预处理的标记流并构建 C 代码的内部结构化表示==。** 

这种表示以 Box64 可以用于更深入分析和代码生成的方式描述声明、函数定义、表达式和语句。这就像构建 C 代码组件及其关系的清晰、详细的图表。

### 用例：解析简单的 C 程序

让我们考虑 Box64 的 `wrapperhelper` 可能处理的一个小型 C 程序：

```c
// example.c
#include <stdio.h> // 在第 4 章中预处理

int calculate_sum(int a, int b) { // 函数声明/定义
    int result = a + b;           // 局部变量声明、赋值和表达式
    return result;                // 返回语句
}

void main_func() { // 另一个函数
    int x = 5;                     // 带初始化器的声明
    int y = calculate_sum(x, 10);  // 带函数调用表达式的声明
    printf("Sum: %d\n", y);        // 函数调用表达式
}
```

为了让 Box64 的解析器正确理解这一点，它需要：
1.  识别 `int calculate_sum(int a, int b) { ... }` 是函数定义。
2.  理解 `int a` 和 `int b` 是其参数，`int` 是其返回类型。
3.  在函数内部，识别 `int result = a + b;` 为局部变量声明。
4.  正确解析表达式 `a + b`，理解 `a` 和 `b` 是变量，`+` 是加法运算符。
5.  理解 `calculate_sum(x, 10)` 是函数调用，其中 `x` 和 `10` 是参数。
6.  知道 `printf("Sum: %d\n", y)` 是另一个带有字符串字面量和变量参数的函数调用。

这个解析阶段的输出不是可执行代码；它是一个复杂的内部数据模型（通常称为抽象语法树，或 AST，尽管 Box64 的表示可能不是单一的整体树），它精确地捕获程序的结构。

## Box64 的解析器：构建结构化模型

在预处理器提供 `proc_token_t`（处理过的标记，如 `lang.h` 中所见，并在 [第 4 章：预处理器指令处理](04_preprocessor_directive_handling_.md) 和 [第 5 章：宏系统](05_macro_system_.md) 中讨论）之后，C 代码解析器接管。它使用这些标记来构造表示 C 程序不同部分的专用数据结构。

### 解析器的工具包：内部数据结构

Box64 使用几个关键数据结构（来自 `wrapperhelper/src/lang.h`）来构建其内部模型：

*   **`file_t`**：这是表示整个已解析的 C 源文件的顶级结构。它充当该文件中找到的所有声明、类型定义和常量映射的容器。它保存几个"符号表"（哈希映射）以快速查找信息。
*   **`type_t`**：正如我们在 [第 2 章：C 类型系统表示](02_c_type_system_representation_.md) 中探讨的，这个结构描述*任何* C 数据类型（如 `int`、`int*`、`struct MyData`、`int(*func)(float)`）。解析器在遇到类型声明时构造这些。
*   **`struct_t` / `st_member_t`**：也来自 [第 2 章](02_c_type_system_representation_.md)，这些描述 `struct` 和 `union` 的布局和成员。
*   **`expr_t`**：这个新结构（在 `lang.h` 中定义）用于表示 C 表达式，如 `a + b`、`x * 5` 或 `my_func(arg)`。它捕获操作及其顺序。
*   **`declaration_t`**：这个结构（在 `lang.h` 中定义）表示完整的变量或函数声明，包括其存储类（`static`、`extern`）、其类型（`type_t`）以及是否已完全定义。

这些结构相互连接，形成一个反映 C 代码内复杂关系的网络。

## 概念

解析过程本质上涉及一组相互连接的函数，它们==递归地相互调用，消耗标记并构建这些内部数据结构。这被称为**递归下降解析**==。

### 1. 解析声明

声明是 C 中的基础。它们告诉编译器关于变量、函数和自定义类型的信息。Box64 的解析器使用 `parse_declaration_specifier` 和 `parse_declarator` 等函数来分解声明。

*   **声明说明符**：这些包括关键字，如 `int`、`float`、`struct`、`enum`、`const`、`static` 等。`parse_declaration_specifier` 识别这些并开始构建 `type_t` 对象。
*   **声明符**：声明的这一部分指定正在声明的实体的名称，以及任何指针（`*`）、数组（`[]`）或函数参数（`()`）。`parse_declarator` 负责这个复杂的任务，通常是递归的。

示例：`const int *myArray[10];`
*   `parse_declaration_specifier` 会识别 `const int`。
*   然后 `parse_declarator` 会处理 `*myArray[10]`，将其识别为 10 个指向常量整数的指针的数组。

### 2. 解析表达式

表达式是进行计算和逻辑操作的地方。`parse_expression` 函数处理这个，构造 `expr_t` 对象。C 表达式有关于**运算符优先级**（例如，乘法在加法之前发生）和**结合性**（例如，`a - b - c` 是 `(a - b) - c`）的严格规则。解析器必须遵守这些规则。

*   `parse_expression` 使用涉及"运算符堆栈"的技术来正确构建表达式树，确保操作根据 C 的优先级规则进行分组。
*   它处理简单的值（数字、标识符）、一元操作（`!x`、`*ptr`）、二元操作（`a + b`、`x == y`）、三元操作（`cond ? a : b`）、函数调用等。

## 底层实现：`parse.c` 中的核心解析逻辑

Box64 的 C 代码解析的核心位于 `wrapperhelper/src/parse.c`，与 `wrapperhelper/src/lang.h` 中定义的数据结构一起工作。

### 入口点：`parse_file`

`parse_file` 函数是解析完整 C 源文件的顶级入口点。它接收处理过的标记流（来自 [第 5 章：宏系统](05_macro_system_.md) 的 `preproc_t`）并构建 `file_t` 结构。

```c
// 简化自 wrapperhelper/src/parse.c
file_t *parse_file(machine_t *target, const char *filename, FILE *file) {
    preproc_t *prep = preproc_new_file(target, file, dirname, filename); // 来自第 5 章
    // ... 错误处理和设置 ...

    file_t *ret = file_new(target); // 创建顶级 file_t 容器
    type_t *typ = type_new(); // 当前声明的临时 type_t

    while (1) { // 循环处理标记直到 EOF
        proc_token_t tok = proc_next_token(prep); // 获取下一个处理过的标记
        if (tok.tokt == PTOK_EOF) {
            // 到达文件末尾，解析完成
            goto success;
        } else if ((tok.tokt == PTOK_SYM) && (tok.tokv.sym == SYM_SEMICOLON)) {
            // 空声明（例如，`;;`），只是跳过
            // ...
        } else if (tok.tokt == PTOK_PRAGMA) {
            // 处理特殊的 #pragma 指令
            // ... (详见实际代码) ...
        } else {
            // 主路径：解析声明或定义
            enum decl_storage storage = TMPSTO_NONE; // 例如，static、extern
            enum fun_spec fspec = FSPEC_NONE;       // 例如，inline、noreturn
            enum decl_spec spec = SPEC_NONE;         // 例如，int、struct、typedef

            // 步骤 1：解析类型和存储说明符
            if (!parse_declaration_specifier(target, ret->struct_map, ret->type_map, ret->enum_map, &ret->builtins, ret->const_map,
                                             ret->type_set, prep, &tok, &storage, &fspec, &spec, typ)) {
                goto failed; // 说明符解析期间出错
            }
            if (spec == SPEC_NONE) continue; // 是 static_assert，继续下一个标记

            // 步骤 2：解析声明符（名称、指针、数组、函数签名）
            // 如果下一个标记不是分号，这意味着有声明符（例如，变量名、函数签名）
            if ((tok.tokt != PTOK_SYM) || (tok.tokv.sym != SYM_SEMICOLON)) {
                if (!parse_declarator(target, &(struct parse_declarator_dest_s){.f = ret}, prep, &tok, storage, fspec, typ, 1, 1, 1, 0)) {
                    goto failed; // 声明符解析期间出错
                }
            } else {
                // 没有声明符的声明（例如，`int;`）- 验证它
                if (validate_storage_type(&tok.loginfo, target, storage, typ, tok.tokv.sym) != VALIDATION_LAST_DECL) {
                    goto failed;
                }
                // ... 处理非函数类型的函数说明符 ...
            }
            // 声明之后，为下一个重置
            type_del(typ);
            typ = type_new(); // 为下一个声明准备新的 type_t
            // ... 错误处理 ...
        }
    }
success:
    // ... 清理和最终化 ...
    return ret;
failed:
    // ... 错误清理 ...
    return NULL;
}
```
`parse_file` 驱动整个过程。它使用 `proc_next_token` 持续获取标记，并且对于每个顶级 C 构造，分派到更专门的解析函数，如 `parse_declaration_specifier` 和 `parse_declarator`。它还管理 `file_t` 结构内的全局符号表。

### 解析声明说明符：`parse_declaration_specifier`

此函数负责确定声明的基本类型、存储类和限定符。它重复消耗关键字和标识符，直到它对声明的"说明符"有完整的了解。

```c
// 简化自 wrapperhelper/src/parse.c
static int parse_declaration_specifier(machine_t *target, khash_t(struct_map) *struct_map, khash_t(type_map) *type_map, khash_t(type_map) *enum_map,
        type_t *(*builtins)[LAST_BUILTIN + 1], khash_t(const_map) *const_map,
        khash_t(type_set) *type_set, preproc_t *prep, proc_token_t *tok, enum decl_storage *storage,
        enum fun_spec *fspec, enum decl_spec *spec, type_t *typ) {
    // ... 处理 _Static_assert（如果存在则跳过它）...

parse_cur_token_decl:
    if (tok->tokt == PTOK_EOF) { /* ... 错误 ... */ }

    // 处理存储类说明符（例如，`auto`、`extern`、`static`、`typedef`）
    if (storage && (tok->tokt == PTOK_KEYWORD) && (tok->tokv.kw == KW_AUTO)) {
        // ... 更新 *storage ...
        *tok = proc_next_token(prep); goto parse_cur_token_decl;
    }
    // ... KW_EXTERN、KW_REGISTER、KW_STATIC、KW_THREAD_LOCAL、KW_TYPEDEF 的类似块 ...

    // 处理函数说明符（例如，`inline`、`_Noreturn`）
    if (fspec && (tok->tokt == PTOK_KEYWORD) && (tok->tokv.kw == KW_INLINE)) {
        // ... 更新 *fspec ...
        *tok = proc_next_token(prep); goto parse_cur_token_decl;
    }
    // ... KW_NORETURN 的类似块 ...

    // 处理类型限定符（例如，`_Atomic`、`const`、`restrict`、`volatile`）
    if ((tok->tokt == PTOK_KEYWORD) && (tok->tokv.kw == KW_ATOMIC)) {
        // ... 更新 typ->is_atomic，处理 _Atomic(...) 语法 ...
        *tok = proc_next_token(prep); goto parse_cur_token_decl;
    }
    // ... KW_CONST、KW_RESTRICT、KW_VOLATILE 的类似块 ...

    // 处理类型说明符（例如，`_Bool`、`char`、`int`、`struct`、`enum`、`typedef name`）
    if ((tok->tokt == PTOK_KEYWORD) && (tok->tokv.kw == KW_BOOL)) {
        typ->typ = TYPE_BUILTIN; typ->val.builtin = BTT_BOOL;
        *spec = SPEC_BUILTIN;
        *tok = proc_next_token(prep); goto parse_cur_token_decl;
    }
    // ... KW_CHAR、KW_INT、KW_LONG、KW_SHORT、KW_SIGNED、KW_UNSIGNED、KW_VOID、KW_FLOAT、KW_DOUBLE 的许多类似块 ...
    
    // 处理 struct/union 定义或引用
    if ((tok->tokt == PTOK_KEYWORD) && (*spec == SPEC_NONE) && ((tok->tokv.kw == KW_STRUCT) || (tok->tokv.kw == KW_UNION))) {
        // ... 解析 struct/union 标签和/或成员 {...} ...
        *tok = proc_next_token(prep); goto parse_cur_token_decl;
    }

    // 处理 enum 定义或引用
    if ((tok->tokt == PTOK_KEYWORD) && (*spec == SPEC_NONE) && (tok->tokv.kw == KW_ENUM)) {
        // ... 解析 enum 标签和/或成员 { ENUM_VAL = expr, ... } ...
        *tok = proc_next_token(prep); goto parse_cur_token_decl;
    }

    // 处理 typedef 的名称（引用类型的标识符）
    if ((tok->tokt == PTOK_IDENT) && (*spec == SPEC_NONE)) {
        khiter_t it = kh_get(type_map, type_map, string_content(tok->tokv.str));
        if (it != kh_end(type_map)) {
            *spec = SPEC_TYPE;
            type_copy_into(typ, kh_val(type_map, it)); // 复制 typedef 的类型
            string_del(tok->tokv.str); // 消耗的标识符
            *tok = proc_next_token(prep); goto parse_cur_token_decl;
        }
        // ... 如果不是 typedef 则报错 ...
    }
    // ... 成功返回 1，失败返回 0 ...
}
```
这个函数是一个大循环，不断处理标记，直到遇到*不是*声明说明符的东西。它逐步构建 `typ`（`type_t`）对象并更新 `storage`、`fspec` 和 `spec` 标志。注意它如何处理 `struct` 和 `enum` 定义，它们本身可以包含进一步的声明。

### 解析声明符：`parse_declarator`

`parse_declarator` 函数获取 `base_type`（由 `parse_declaration_specifier` 确定）并对其应用修饰符，如指针、数组和函数参数。这个函数对于复杂类型（如 `int (*myFunc)(int*)`）可能是高度递归的。

```c
// 简化自 wrapperhelper/src/parse.c
static int parse_declarator(machine_t *target, struct parse_declarator_dest_s *dest, preproc_t *prep, proc_token_t *tok, enum decl_storage storage,
      enum fun_spec fspec, type_t *base_type, int is_init, int is_list, int allow_decl, int allow_abstract) {
    type_t *typ = base_type; ++typ->nrefs; // 从基本类型开始

    // 处理嵌套指针/括号的堆栈（例如，`int **ptr`）
    VECTOR(size_t) *nptr_stack = vector_new_cap(size_t, 1);
    vector_push(size_t, nptr_stack, 0); // 存储当前级别的 '*'（指针）计数

    while (1) {
        switch (tok->tokt) {
        case PTOK_IDENT:
            // 这是正在声明的实际名称（例如，`myVar`）
            // ... 存储 cur_ident ...
            *tok = proc_next_token(prep); break;
        case PTOK_SYM:
            if (tok->tokv.sym == SYM_LPAREN) { // 括号开始
                if (has_ident) { // 如果我们已经看到标识符，这是函数
                    // ... 递归解析函数参数 ...
                    type_t *new_typ = type_new_function_type(...);
                    // ... 将 new_typ 链接到现有类型链（typ）...
                    *tok = proc_next_token(prep); break;
                } else { // 它只是分组括号（例如，`int (*ptr)`）
                    vector_push(size_t, nptr_stack, 0); // 为 () 内的指针推入新级别
                    *tok = proc_next_token(prep); break;
                }
            } else if (tok->tokv.sym == SYM_STAR) { // 指针声明符
                if (has_ident) { /* ... 错误：`int my_var *` 无效 ... */ }
                type_t *new_typ = type_new_ptr(typ); // 创建新的指针类型
                typ = new_typ; // 更新正在构建的当前类型
                ++vector_last(size_t, nptr_stack); // 增加当前级别的指针计数
                *tok = proc_next_token(prep); break;
            } else if (tok->tokv.sym == SYM_LSQBRACKET) { // 数组声明符 `[`
                // ... 解析数组大小表达式、类型限定符（static、const）...
                type_t *new_typ = type_new_array_type(...);
                // ... 将 new_typ 链接到现有类型链（typ）...
                *tok = proc_next_token(prep); break;
            } else if (tok->tokv.sym == SYM_RPAREN) { // 括号结束 `)`
                // ... 从 nptr_stack 弹出，应用指针 ...
                *tok = proc_next_token(prep); break;
            } else if (tok->tokv.sym == SYM_SEMICOLON || tok->tokv.sym == SYM_COMMA || tok->tokv.sym == SYM_EQ) {
                // 变量、函数或 typedef 的声明符结束。
                // 验证最终类型，存储声明（如果适用），处理初始化器。
                // ... 在 `dest` 中存储 `declaration_t` 或 `type_t` 的逻辑 ...
                goto success;
            }
            // ... 其他符号 ...
        // ... 其他标记类型 ...
        }
    }
success:
    // ... 清理 ...
    return 1;
failed:
    // ... 错误清理 ...
    return 0;
}
```
`parse_declarator` 是一个复杂的状态机。它处理声明中运算符的优先级。例如，`int *arr[10]` 是指针数组，而 `int (*ptr_to_func)(int)` 是指向函数的指针。堆栈（`nptr_stack`）帮助管理这种嵌套。如果指定了数组大小（例如，`int arr[SOME_CONSTANT];`），它还可以递归调用 `parse_expression`。

### 解析表达式：`parse_expression`

这个函数可以说是 C 解析器最复杂的部分，因为它需要处理运算符优先级、结合性、函数调用以及各种 C 构造，如 `sizeof`。

```c
// 简化自 wrapperhelper/src/parse.c
// expr_level 用于管理运算符优先级（更高的级别意味着更高的优先级）
static expr_t *parse_expression(machine_t *target, khash_t(struct_map) *struct_map, khash_t(type_map) *type_map, khash_t(type_map) *enum_map,
        type_t *(*builtins)[LAST_BUILTIN + 1], khash_t(const_map) *const_map,
        khash_t(type_set) *type_set, preproc_t *prep, proc_token_t *tok, int expr_level) {
    
    VECTOR(expr_pops) *op_stack = vector_new(expr_pops); // 运算符和部分表达式的堆栈
    expr_t *e = NULL; // 正在构建的当前表达式

expr_new_token:
    if (tok->tokt == PTOK_IDENT) { // 变量名
        e = malloc(sizeof *e); e->typ = ETY_VAR; e->val.var = tok->tokv.str;
        *tok = proc_next_token(prep); goto expr_new_token;
    } else if (tok->tokt == PTOK_NUM) { // 数字字面量
        e = malloc(sizeof *e); e->typ = ETY_CONST;
        num_constant_convert(&tok->loginfo, tok->tokv.str, &e->val.cst, target->size_long == 4);
        string_del(tok->tokv.str);
        *tok = proc_next_token(prep); goto expr_new_token;
    } else if (tok->tokt == PTOK_STRING) { // 字符常量（例如，'a'）
        // ... 处理字符常量 ...
        *tok = proc_next_token(prep); goto expr_new_token;
    }

    // 使用辅助宏处理一元运算符（++、--、&、*、-、!）
    // 示例：UNOP(SYM_PLUS, UOT_POS, 2, 3) 表示 '+' 作为一元前缀，级别 2，右结合到级别 3
    // ... ++、--、&、*、+、-、~ 的 UNOP 宏 ...
    
    // 使用辅助宏处理二元运算符（+、-、*、/、==、&&、|| 等）
    // 示例：BINOP(SYM_PLUS, BOT_ADD, 5, 5, 4) 表示 '+' 作为二元运算符，级别 5，左结合，左参数级别 5，右参数级别 4
    // ... +、-、*、/、%、<<、>>、<、>、<=、>=、==、!=、&、^、|、&&、||、=、+= 的 BINOP 宏 ...
    
    // 处理三元运算符（condition ? true_expr : false_expr）
    // ... SYM_QUESTION 和 SYM_COLON ...

    // 处理 `sizeof` 和 `_Alignof` 关键字
    if ((tok->tokt == PTOK_KEYWORD) && (tok->tokv.kw == KW_SIZEOF)) {
        // ... 解析 sizeof(type) 或 sizeof(expression) ...
        // 如果是 `sizeof(type_name)`，它调用 `parse_type_name`
        // ... 创建带有大小的 ETY_CONST expr ...
        *tok = proc_next_token(prep); goto expr_new_token;
    }
    // ... _Alignof ...

    // 处理带括号的表达式 `(expression)` 和函数调用 `func(args)`
    if ((tok->tokt == PTOK_SYM) && (tok->tokv.sym == SYM_LPAREN)) {
        // 如果 has_level != -1，这是函数调用（例如，`my_func()`）
        // 否则，它只是带括号的表达式或强制转换 `(type)expr`
        // ...
        *tok = proc_next_token(prep); goto pushed_expr;
    }
    
    // 处理标记后，检查运算符堆栈以应用优先级规则
    if (vector_size(expr_pops, op_stack)) {
        // 从堆栈弹出运算符，根据优先级规则应用到 `e`（`expr_level`、`once_done_want_level`）
        // ... 应用运算符、创建 ETY_UNARY、ETY_BINARY、ETY_TERNARY、ETY_CAST 节点的复杂逻辑 ...
        goto expr_new_token; // 继续使用新的 `e`
    }
    
    // 如果堆栈为空且我们有完整的表达式 `e`，返回它
    if ((vector_size(expr_pops, op_stack) == 0) && (e != NULL)) {
        vector_del(expr_pops, op_stack);
        return e;
    }
    
    log_error(&tok->loginfo, "invalid expression: unexpected token\n");
    // ... 清理 ...
    return NULL;
}
```
`parse_expression` 是递归下降解析与运算符优先级解析技术（通常使用调度场算法或类似逻辑）结合的典型例子。它创建 `expr_t` 节点（如 `ETY_VAR`、`ETY_CONST`、`a+b` 的 `ETY_BINARY`、`(int)x` 的 `ETY_CAST`）并将它们链接在一起以形成表达式的表示。`expr_level` 参数和 `op_stack` 是正确处理运算符优先级（例如，`*` 比 `+` 绑定更紧）的关键。

### 评估常量表达式：`eval_expression`

在构建 `expr_t` 之后，有时 Box64 需要知道其实际值（例如，对于数组大小 `int arr[10 + 5];` 或 `#if` 预处理器指令）。`eval_expression` 函数正是这样做的。

```c

    // 递归评估表达式树 `e`
    switch (e->typ) {
    case ETY_VAR: // 如果是变量，在 `const_map` 中查找它（对于定义的常量）
        // ... 在 const_map 中查找 ...
        return 0; // 大多数变量不是常量
    case ETY_CONST: // 已经是常量，只返回其值
        *dest = e->val.cst; return 1;
    case ETY_UNARY: // 评估子表达式，然后应用一元运算
        if (!eval_expression(li, target, e->val.unary.e, const_map, dest, fatal)) return 0;
        // ... 应用 UOT_NEG、UOT_ANOT、UOT_BNOT 操作 ...
        return 1;
    case ETY_BINARY: { // 评估两个子表达式，然后应用二元运算
        num_constant_t dest1, dest2;
        if (!eval_expression(li, target, e->val.unary.e1, const_map, &dest1, fatal)) return 0;
        if (!eval_expression(li, target, e->val.binary.e2, const_map, &dest2, fatal)) return 0;
        promote_csts(&dest1, &dest2); // 确保计算的一致类型
        // ... 根据 dest1.typ 执行 BOT_ADD、BOT_SUB、BOT_MUL 等 ...
        return 1;
    }
    case ETY_TERNARY: // 评估条件，然后选择两个分支之一
        // ...
        return 1;
    case ETY_CAST: // 评估子表达式，然后强制转换结果
        // ... 应用强制转换规则（例如，float 到 int）...
        return 1;
    // ... 其他表达式类型（如函数调用不是常量）...
    }
    return 0; // 表达式不是常量或评估失败
}
```
`eval_expression` 对于评估 `static_assert` 条件或由简单算术定义的数组大小等任务至关重要。它递归遍历 `expr_t` 结构，执行操作，并返回包含最终值的 `num_constant_t`。它还包括 `promote_csts` 来处理 C 算术中的类型提升规则，确保 `1.0 + 2` 正确变为 `3.0`。

## 结论

在本章中，我们探讨了 Box64 的"C 代码解析"系统，这是预处理后理解 C 语言语法的关键步骤。我们了解了 Box64 如何==获取预处理的标记流==，并使用 `file_t`、`type_t`、`expr_t` 和 `declaration_t` 等结构构建详细的内部表示。

研究了 `parse_file`、`parse_declaration_specifier`、`parse_declarator` 和 `parse_expression` 等==函数如何协同工作，通常是递归的==，以准确建模 C 代码，甚至处理运算符优先级和类型修饰等复杂方面。

对 C 代码语法结构的这种强大理解是 Box64 构建其仿真能力的基石。有了 x86_64 C 程序的完整内部模型，Box64 终于准备好执行其核心魔法：==生成专门的包装器代码以在 ARM64 系统上运行它==。这就是我们将在下一章探讨的内容：[包装器代码生成逻辑](07_wrapper_code_generation_logic_.md)。
